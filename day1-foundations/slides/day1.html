Module 1

Claude & the Messages API

Concept

The model family

  • Haiku — fastest, cheapest. High-volume, well-specified tasks: classify, extract, format.
  • Sonnet — balanced. Code, review, multi-step tool use.
  • Opus — deepest reasoning. Ambiguous, open-ended problems.
  • Newer generation numbers (4.5, 5, …) = smarter at the same tier.

Exam watch Default to the most capable model, then step down only when measurement says you can — not "pick a tier by task type". (Day 5 goes deep.)

Our labs pin claude-haiku-4-5 — a classroom of keys, kept cheap.

Concept

One endpoint: /v1/messages

  • Everything goes through client.messages.create(...) (or .stream(...)).
  • Tools, images, PDFs, structured output, thinking — parameters of this one call, not separate APIs.
  • The API is stateless — no "session" on the server.
resp = client.messages.create(
    model="claude-haiku-4-5", max_tokens=400,
    system="You explain code for a teammate.",
    messages=[{"role": "user", "content": "..."}],
)
tools=[...]  thinking={"type":"adaptive"}  output_config={...}   # same call

Module 2

Prompt-engineering fundamentals

Concept

The system prompt is the steering wheel

  • The role, the rules, the output shape — it persists across every turn.
  • User messages carry the task and the data; the system prompt carries the contract.
  • Heuristic: if you'd repeat it every turn, it belongs in system.
system=(
  "You review Python for a teammate who will maintain it. "
  "One tight paragraph. No line-by-line. No praise."
)
Concept

Be explicit · structure · show don't tell

Be explicit

State the format, length, audience, what to exclude. Ambiguity is answered by the model guessing.

Structure with tags

Wrap inputs in <code>, <doc>, <transcript> — separates instruction from data.

Few-shot

One or two worked input → output examples beat a paragraph of description for format-following.

Concept

Steering the output shape

  • Say the shape in the system prompt: "exactly three bullets, no preamble."
  • Give a skeleton to fill in. Name the sections you want.
  • For a guaranteed machine-readable shape → structured outputs / strict tools (Day 2).
  • Prefill (words in Claude's mouth as the last assistant turn) is removed on current models.
Exam watch

Thinking & effort

  • Current models take thinking={"type": "adaptive"} — the model decides how much.
  • The old fixed budget_tokens is deprecated / rejected on current models. A classic stale-answer distractor.
  • output_config={"effort": "low|medium|high|xhigh|max"} dials thoroughness vs cost.
  • Reach for thinking on ambiguous, multi-step problems; skip it for classify/extract.

Module 3

Streaming

Concept

Streaming stops the timeout

  • Non-streaming holds the HTTP connection until the whole answer is done — big outputs can time out and fail.
  • Streaming = tokens as they're generated (Server-Sent Events, not a WebSocket). No timeout risk, live UI.
  • Errors can arrive as an event mid-stream — read events, not just the status code.
with client.messages.stream(model=M, max_tokens=400, messages=msgs) as stream:
    for chunk in stream.text_stream:
        print(chunk, end="", flush=True)
final = stream.get_final_message()   # full Message: usage, stop_reason, blocks

Module 4

Errors, retries, timeouts

Exam watch

Catch a chain — retry or fail fast

A single except Exception throws the distinction away. refusal is not an exception — it's a stop_reason.

1:19:58 · L9
Concept

The SDK already does some of this

  • Built-in: retries 408 / 409 / 429 / 5xx + connection errors, exponential backoff, max_retries default 2.
  • Built-in: ~10-minute default timeout; override with client.with_options(timeout=30.0).
  • Hand-roll a loop only for custom logic — honour retry-after, a wall-clock budget, structured logging.
  • rate_limit = your traffic spiked (yours to fix). overloaded = their load (not yours).

Module 5

Tokens, cost & the agentic loop

Concept

Count before you spend

  • count_tokens(model=, system=, messages=, tools=) — a separate, cheap endpoint. No max_tokens.
  • Use it to predict spend, or to check a prompt will fit the context window.
  • Cost = tokens × (price-per-million ÷ 1e6). Output is dearer than input.
  • usage.cache_read_input_tokens ≈ 0.1× input price — Day 5's caching lever.
counted = client.messages.count_tokens(model=M, system=S, messages=msgs)
est = counted.input_tokens * (1.00 / 1_000_000)   # Haiku input $/tok

The agentic loop · a while-loop in a trench coat

Rule 1 — after every response, append {"role":"assistant","content": response.content} (the whole block list).

Rule 2 — on tool_use: run each block, then append one user message of tool_result blocks, ids matching.

user → assistant(tool_use) → user(tool_result) → assistant(text)

Handle max_tokens / refusal. Cap the turns.
