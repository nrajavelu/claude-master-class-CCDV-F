The method — every question is one of four decisions

Rule 1 — the stem names a constraint → the answer is the mechanism built for it; a generic knob (temperature, model tier, max_tokens, "raise the timeout") is a distractor.
Rule 2 — if the stem says must / never / always / cannot, guidance ("tell the model to…", "write it down") is dead; only a mechanism (isolation, a blocking hook, a schema) survives. "A polite request is not an enforceable control."

The Messages API

One endpoint. client.messages.create / .stream. Tools, vision, PDF, thinking, structured output are parameters — not separate APIs. Token counting is the one separate endpoint.
Stateless. No server session. Multi-turn = you resend the whole messages list every call.
Request = model + max_tokens (both required) + system (own field — no role:"system" message) + messages (first must be user).
Response = content (a LIST of typed blocks — check block.type) + stop_reason (branch on it) + usage (your bill). You send dicts, get back objects.

stop_reason — all of them

  • end_turn — read the text · max_tokens — raise it / stream / narrow
  • tool_use — run it, feed results back · stop_sequence — expected
  • pause_turn — resend to continue · refusal — HTTP 200, not an exception; check stop_details before reading content
  • Not Claude values: tool_call, content_filter, token_limit, function_call — distractors.

Streaming

  • Server-Sent Events over the same HTTP call — not a WebSocket.
  • Non-streaming holds the connection until done → long outputs can time out. Stream anything long.
  • An error can arrive as an event mid-stream — read events, not just the status code.
  • stream.get_final_message() after the with block gives the complete Message (usage, stop_reason, blocks). Don't hand-assemble.

Errors — retry or fail fast

  • Catch a chain, most-specific first. A single except Exception loses the distinction.
  • SDK already retries 408/409/429/5xx + connection, max_retries=2, ~10-min timeout.
  • rate_limit = your spike (yours to fix). overloaded = their load.

Tokens & cost

  • count_tokens(model, system, messages, tools) — separate cheap endpoint, no max_tokens. Predict spend / check fit.
  • Cost = tokens × (price-per-million ÷ 1e6). Output dearer than input.
  • cache_read_input_tokens ≈ 0.1× input price (a cache write ≈ 1.25×).

The agentic loop

  • Rule 1 — after every response append {"role":"assistant","content": response.content} (the whole list).
  • Rule 2 — on tool_use: one user message, a list of tool_result blocks, tool_use_ids matching.
  • Loop until end_turn; handle max_tokens / refusal; cap the turns.
