Module 1

Model selection & trade-offs

Exam watch

The trade-off triangle

  • Start capable — the most capable model at lower effort often beats a smaller model at high effort.
  • Measure on a sample of real requests, with an eval. Step down only when quality holds.
  • The exam prices the decision: a classifier at 1M req/day → the fast tier, and route the hard cases up a tier.
  • Cascading — cheap first, escalate on failure — beats paying premium for every request.
Build-along · Ep 10
Exam watch

Latency vs throughput — different corners

  • A chat interface cares how fast the first token arrives. A pipeline cares how many documents per hour.
  • Streaming changes perceived latency. Batch changes cost. Neither changes the model's intelligence.
  • Every requirement in a scenario — real-time · overnight · high-volume · budget cap — maps to one corner of that trade space. The exam hands you requirements and watches whether you find the corner.

input_tokens is not your input

Module 3

Prompt caching

Exam watch

Prefix match — stable first

  • Any byte change in the prefix invalidates everything after it.
  • Silent invalidators: datetime.now() in the system prompt, unsorted json.dumps, a varying tool set.
  • Verify with usage.cache_read_input_tokens — 0 across repeats = something's invalidating.
  • Cache read ≈ 0.1× input price · cache write ≈ 1.25×.

Batch

Exam watch

Results come back in any order

~50% cost, non-latency-sensitive. "10,000 documents overnight, cost matters, nobody waits" → Batch. Not "run in parallel", not "cap tokens".

Module 5

Reliability

Concept

Three places a call can break

  • Before it leaves — 400 bad request. Fail fast.
  • In transit — 429 rate_limit (your spike, yours to fix) · overloaded (their load) · connection. Back off + retry.
  • After HTTP 200 — truncation (max_tokens) · refusal (check stop_details, don't blind-retry) · wrong shape (validate).

SDK retries 408/409/429/5xx + connection, max_retries=2. On streams, an error can arrive as an event mid-stream.

Module 6

Vision & documents

Exam watch

An image is built-in tokens

  • An image rides as another content block in the same messages list — no separate endpoint.
  • It's cut into patches → a bigger picture is a bigger bill. If you have the text, send the text.
  • A PDF is billed twice — once as its text, once as each page rendered to an image.
  • Animations count by their first frame. Citations: set citations:{enabled:true} on each document block.

Concept

Identity, secrets & keys

  • Keys in a secret store / .env + .gitignore — never the repo. Rotate on leak.
  • Least privilege — a fine-grained, read-only PAT scoped to one repo.
  • Env-var expansion in config: ${GITHUB_PAT}, not the literal.
  • Self-hosted ≠ air-gapped — web_search / web_fetch still run on Anthropic's servers.

Module 8

Exam day

Exam method

The routine, at speed

  • ~135 sec / item (53 in 120 min, keep ~10 min for flags). Over 2.5 min → flag & move.
  • Read the last sentence of the stem first — "best", "select two", "will NOT".
  • Name the decision → kill stale-API + generic-knob options → if must/never, kill guidance → pick the mechanism → tie-break to cheaper / simpler / SDK-native.
  • Multiple-response: select exactly the number asked. No blanks — no negative marking.
