Exam practice

How to work an item — read · note · eliminate
  1. Read the stem twice. Underline the constraint word — must, never, always, cannot, only, cheapest, overnight, high-volume, one call. That word decides the answer.
  2. Name the decision. ① what runs · ② how it calls Claude · ③ what Claude sees & says · ④ will it survive production. Write the number in the notes box.
  3. Rule 1 — mechanism beats knob. A generic dial (temperature, model tier, max_tokens) is almost always a distractor when the stem names a constraint.
  4. Rule 2 — mechanism beats guidance. On a must / never stem, every option that is only advice ("tell the model to…", "write it down", "ask users to…") is dead.
  5. Name ≥ 2 wrong-answer species before you pick — say why each loser loses: overbuildsymptom-treaterextremist true-but-irrelevantstale-API right-word-wrong-placewrong-system
  6. Pick the elegant minimal fix. The developer exam punishes over-engineering — the smallest thing that actually removes the failure wins.

Use the notes box under each question to jot your constraint word, decision number, and species guesses before you hit Check. Your notes are saved on this device.
