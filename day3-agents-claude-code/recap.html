Should you build an agent?

  • All four must be yes: complexity · value · viability · cost of error (can mistakes be caught?). Any "no" → one call or a code-controlled workflow.

Four ways to build one — harness × deployment

  • Manual loop — you write the harness, you host.
  • Tool Runner — SDK drives the loop over your tools; you host. Per-turn hooks.
  • Claude Agent SDK — Claude Code as a library (built-in tools); you host.
  • Managed Agents — Anthropic runs the loop and hosts a per-session sandbox.
  • Tool Runner ≠ Claude Agent SDK (different packages). Only Managed Agents adds managed deployment.

Hooks — code the model can't talk out of

  • PreToolUse — approve / deny (the mechanism answer to a must/never stem).
  • PostToolUse — transform · taint external text as untrusted.
  • Stop — reads the transcript; a review can't END until a comment was posted.
  • PreCompact — observe only; by the time it fires it's too late to save anything.

Subagents — usually fewer

  • Coordinator fans out to subagents, each with own fresh context, narrow tools, own model. Each one adds context/latency/cost — fan out only when work truly parallelises or one loop would fill its context with reading.

Claude Code

  • Project config discovered cwd → repo root: CLAUDE.md, .claude/skills/, .claude/commands/, .mcp.json. Both a subfolder and root file apply.
  • A rules file's content arrives as a user message, not system.
  • Headless: claude -p "..." for CI. setting_sources=["project"] gates it in the SDK.

MCP — not a bag of tools

  • MCP is a protocol. .mcp.json transports: stdio (a local command) · http (remote URL + headers) · sse.
  • A remote server exposes dozens of tools — scope allowed_tools. Secrets via ${ENV_VAR}.
  • A plugin runs code with your privileges — installing it is a trust decision.
