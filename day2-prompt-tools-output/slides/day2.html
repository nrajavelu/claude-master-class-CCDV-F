Module 1

Prompt engineering, deliberately

Concept

Contract in system · task in messages

  • Role, rules, output shape → system. It applies to every turn.
  • The changing task and the data → messages.
  • Heuristic: if you'd paste it every turn, it's a system prompt.
system="You extract fields from support tickets. Output only what the schema asks for."
messages=[{"role":"user","content": "<ticket>...</ticket>"}]
Concept

Explicit · structure · show don't tell

Be explicit

Format, length, audience, exclusions. Ambiguity is answered by a guess.

Structure with tags

<doc>, <ticket>, <example> — instruction ≠ data. First line of injection defence.

Few-shot

One or two input → output pairs beat a paragraph of rules. Called zero/one/multi-shot.

Exam watch two prompts both correct → the exam prefers the shorter one with a concrete example.

Module 5

Structured output you can trust

Exam watch

Asking is not making sure

  • strict is a field on the tool definition; schema needs additionalProperties:false + everything in required.
  • No "optional" — optional = allow null as a type.
  • Unsupported schema features are rejected, not ignored.
  • client.messages.parse() validates the response against your schema for you.
1:00:52 · L7
Concept

Validate, don't hope

def validate_finding(args) -> list[str]:   # returns specific problems
    errors = []
    if args.get("severity") not in ("blocking","warning","nit"):
        errors.append("severity must be one of ... — got %r" % args.get("severity"))
    return errors

On the SDK's @tool path strict isn't forwarded yet — the schema guides, validate() enforces. Send precise errors back so the model can fix and resubmit.

Recap

Day 2 · what you can do now

  • Put the contract in system; structure inputs with tags; steer format with an example.
  • Name the surface: chat vs coding-rules vs API — and know where instructions land on each.
  • Keep untrusted content in tool_result; keep your instructions out of it.
  • Write a tool description the model obeys; enforce output with strict + a validator.
